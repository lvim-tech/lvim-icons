1. INTRODUCTION                                           *lvim-icons-intro*

lvim-icons resolves a filename, extension, filetype or filesystem kind to a
renderable icon: >

    { glyph = "", hl = "LvimIconOrange", color = "#dea584", width = 1, name = "rust" }
<
Colours come from the LIVE lvim-utils palette (not a hardcoded hex per icon),
so icons harmonise with the active theme and re-derive on a colorscheme
change. It is the single icon provider for the lvim-tech set; other plugins
resolve their file/ft icons here (a soft dependency — a consumer pcall-requires
it and degrades to one default glyph).

Three render modes:

  nerd (default)  Every icon a single-width Nerd Font glyph, as text, with a
                  palette highlight group. Works in every terminal.
  mix             File / folder icons as Material Icon Theme images (the
                  ones VS Code shows); UI icons as Nerd glyphs.
  material        File / folder icons as in mix; UI icons as images of their
                  own Nerd glyph, in their owner's colour.

An image is two cells wide and drawn through kitty unicode placeholders: sent
once, then two placeholder cells of text, so it works anywhere text does
(buffers, floats, statuslines). Where the terminal cannot show images every
icon is its Nerd glyph as text, whatever the mode.

Every result carries `width` (1 for a font glyph, 2 for an image) so a
consumer aligns columns from it, and `image` — an image must be painted
through its `hl`, whose foreground is the image id.

==============================================================================
2. REQUIREMENTS                                    *lvim-icons-requirements*

Neovim >= 0.10 and lvim-utils (palette + highlight engine). lvim-ui is
optional — it powers the |:LvimIcons| gallery. Icons as images additionally need
lvim-image (libvips draws the SVGs) and a terminal that shows kitty unicode
placeholders: kitty or Ghostty — inside tmux or zellij only when they pass
them through (lvim-image's `tmux_placeholders` / `zellij_placeholders`).

3. SETUP                                                  *lvim-icons-setup*

setup() is optional — the nerd-mode defaults work without it. Call it to
change the render/colour mode, add overrides, or register |:LvimIcons|. >lua

    require("lvim-icons").setup({
        mode = "nerd",          -- "nerd" | "mix" | "material"
        color_mode = "brand",   -- "brand" (real colours) | "theme" | "theme_brand"
        brand_blend = 0.7,      -- theme_brand: keep this much brand hue (1.0 = raw)
        svg = {
            dir = nil,          -- your own SVGs, before the bundled Material set
            fill = 0.72,        -- icon size as a fraction of the cell height
        },
        default = { glyph = "", role = "fg", name = "default" },
        overrides = { extensions = {}, filenames = {}, filetypes = {}, special = {} },
    })
<
setup() merges user options into the live config in place (via
lvim-utils.utils.merge), so every reader of require("lvim-icons.config") sees
the effective values.

4. API                                                      *lvim-icons-api*

                                                          *lvim-icons.get()*
require("lvim-icons").get({name}, {opts})
    Resolve an icon for a path or bare filename through the full lookup chain
    and return a result table (see |lvim-icons-intro|). Always renderable.

    {opts} (optional):
        filetype  string  Filetype hint used when the name is weak
                          (help, qf, terminal, pickers).
        kind      string  A filesystem kind — short-circuits the chain:
                          "directory", "directory_open", "directory_empty",
                          "symlink", "symlink_dir", "symlink_broken",
                          "executable", "file".

    Resolution order: exact basename -> extension tail (longest first, so
    `test.tsx` beats `tsx`) -> {opts.filetype} -> the configured default.

                                                 *lvim-icons.by_extension()*
require("lvim-icons").by_extension({ext})
                                                  *lvim-icons.by_filename()*
require("lvim-icons").by_filename({filename})
                                                  *lvim-icons.by_filetype()*
require("lvim-icons").by_filetype({ft})
                                                      *lvim-icons.by_kind()*
require("lvim-icons").by_kind({kind})
    Direct single-table lookups (no chain). Each returns the default result
    when the key is unmapped.

                                                          *lvim-icons.all()*
require("lvim-icons").all()
    Every icon, materialised and sorted by name — for a custom gallery/audit.

                                                  *lvim-icons.active_mode()*
require("lvim-icons").active_mode()
    The EFFECTIVE render mode after fallback resolution ("nerd", "mix" or
    "material").

                                                     *lvim-icons.override()*
require("lvim-icons").override({overrides})
    Merge additions/overrides into the live data tables at runtime. Same shape
    as the setup `overrides` field.

5. RENDER MODES                                           *lvim-icons-modes*

`mode` selects how glyphs are emitted:

    "nerd"      Every icon a Nerd glyph, as text (the default).
    "mix"       File / folder icons as Material Icon Theme images; UI icons
                as Nerd glyphs.
    "material"  File / folder icons as in mix; UI icons as images of their
                own Nerd glyph.

Images need a terminal that shows kitty unicode placeholders; elsewhere every
icon is its Nerd glyph as text.

                                                         *lvim-icons.ui()*
require("lvim-icons").ui({opts})
require("lvim-utils.icons").ui({opts})
    A UI icon (not a file / folder). `opts.glyph` is the caller's Nerd glyph,
    `opts.hl` its colour group (or `opts.color` a hex). In nerd / mix, or
    with no images, the result is that glyph and group; in material an image
    of that glyph (its SVG extracted from Symbols Nerd Font) filled with the
    group's colour and re-filled on a theme change. Your own SVG for a glyph:
    `svg.dir`/nerd/<CODEPOINT>.svg.

The file / folder SVGs are the bundled Material Icon Theme set (MIT, assets/material/) or
your own: `svg.dir` is searched first, by the same file names (the
Material icon ids, e.g. rust.svg, folder-git-open.svg). Which icon a
file or folder gets is decided by the theme's own manifest
(assets/material/material-icons.json, the file VS Code reads): exact name,
then the longest extension, then the filetype; folders by name, open ones
from the "expanded" table. Each image is drawn into the exact pixels of
its two cells (`svg.fill` = icon size as a fraction of the cell height) and
redrawn under the same id when the cell size changes. An image is two cells
wide — always align columns from the returned `width`. |:checkhealth| reports
the terminal state, the image size and the active mode.

6. COLOURS                                              *lvim-icons-colours*

`color_mode` selects where an icon's colour comes from — three modes:

    "brand"        The icon's REAL upstream brand colour, verbatim — INDEPENDENT
                   of the theme (the classic nvim-web-devicons look, each file
                   type in its own brand colour). (The default.)
    "theme"        Each icon takes a palette role (blue/green/red/…). Self-
                   theming: the LvimIcon<Role> groups re-derive on every
                   colorscheme / palette sync, so icons follow the theme.
    "theme_brand"  The brand colour blended toward the theme background by
                   `brand_blend` (a mix: the brand hue pulled into the theme).
                   1.0 = raw brand colour, lower pulls it toward the background.

The mode can also be overridden PER CALL: >lua

    require("lvim-icons").get(name, { color_mode = "brand" })
<
so a consumer chooses a mode without touching the global config. Each lvim-tech
consumer exposes an `icon_color_mode` option that forwards here.

7. OVERRIDES                                          *lvim-icons-overrides*

Add or replace icons via `overrides` (in setup) or |lvim-icons.override()|.
An override spec is: >lua

    { glyph = "", role = "orange", brand = "#ff5d01", name = "astro" }
<
    glyph  string   Nerd Font glyph (the font-mode character)
    role   string   Palette role: red/green/blue/cyan/magenta/orange/yellow/
                    purple/teal/fg
    brand  string   Upstream brand hex (#rrggbb) — used in "brand"/"theme_brand"
    name   string   Stable icon id (the gallery label)

The same shape overrides a BUILT-IN (recolour or reglyph it) or adds a new one.
The bundled set covers ~300 extensions/filenames/filetypes; anything unmapped
falls back to `default` — extend it here rather than editing the plugin.
Keys are lower-case extensions / filetypes and exact filenames; the `special`
table is keyed by KIND (directory / symlink / executable / …). Example: >lua

    require("lvim-icons").setup({
        overrides = {
            extensions = { astro = { glyph = "", role = "orange", name = "astro" } },
            filenames  = { ["flake.nix"] = { glyph = "", role = "blue", name = "nix" } },
        },
    })
<

8. COMMAND                                              *lvim-icons-command*

                                                              *:LvimIcons*
:LvimIcons
    Open a searchable icon gallery through the canonical lvim-ui picker.
    Confirming a row yanks its glyph to the unnamed and "+" registers — handy
    when authoring another plugin's UI. Registered by setup() (needs lvim-ui).

:LvimIcons mode {nerd|mix|material}                       *:LvimIcons-mode*
    Switch the render mode live, without a restart (no argument: show the
    current one). Same as `require("lvim-icons").set_mode(mode)`, which fires
    `User LvimIconsMode` (data = { mode, previous }); lvim-ui panels, the
    lvim-hud bars and the lvim-tech plugins draw their icons again on it.

==============================================================================
9. HIGHLIGHTS                                        *lvim-icons-highlights*

Font mode defines one group per palette role, self-themed from lvim-utils and
overwritable by a colorscheme or your own setup:

    LvimIconRed        LvimIconGreen      LvimIconBlue
    LvimIconCyan       LvimIconMagenta    LvimIconOrange
    LvimIconYellow     LvimIconPurple     LvimIconTeal
    LvimIconFg

Brand mode additionally creates LvimIconBrand_<hex> groups on demand.

==============================================================================
10. HEALTH                                               *lvim-icons-health*

                                              *:checkhealth-lvim-icons*
:checkhealth lvim-icons
    Reports dependency presence, config validity, a single-width audit of every
    glyph, and — for the image modes — lvim-image, whether the terminal shows
    unicode placeholders, the image size, any mapped icon without its SVG,
    and the resulting active render mode.
